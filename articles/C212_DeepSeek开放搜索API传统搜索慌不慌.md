# DeepSeek开放搜索API传统搜索慌不慌

先说一个数字：0.005 元。

这是 DeepSeek 一次搜索请求的价钱。一千次 5 元，折下来一次半分钱。

第一次看到这个价格时，我想到的不是「便宜」，是另一件事——**它按「次」收钱，不按「位置」收钱。**

这两句话只差一个词，差的是整套生意。

10 月 17 日 DeepSeek 开放了自研搜索的两个接口，Search 找网页，Fetch 取正文。科技媒体的报道大多落在「又多了个搜索入口」和「便宜」上。真正的分水岭藏在计费条款里，不在价格上。

## 一、把计价规则读完，性质就变了

官方文档里有一句，是理解整件事的关键：

> Search and Fetch are billed per successful request, not by tokens or by the number of returned results.

—— DeepSeek API Docs《Search & Fetch》，api-docs.deepseek.com/guides/search（2026-10-20 核，未登录可读）

翻译过来：**按「成功请求」计费，不按 token，也不按返回条数。**

三件事要连起来看才算看全。

**单价。** Search 与 Fetch 各 0.75 美元／千次；中文文档写 5 元／千次，两个币种口径对应，是同一个价。

**条数不改变单价。** `count` 这个参数控制返回几条结果，默认 10，上限 50。文档明确说它只影响返回条数，不影响按请求计价。也就是说，**要 1 条和要 50 条，花一样多的钱。**

**失败不收钱。** 只有返回 HTTP 200 且确实有结果（搜索返回非空数组、抓取返回正文）才计一次。空结果、超时、报错都不计。

这三条凑在一起，性质就变了。

按点击计费的广告系统，收入和你「被看见多少次」强绑定——所以要位置、要首屏、要曝光。而按成功请求计费的检索，收入只和「被问了多少次」绑定。**它不卖看客，它卖结果。**

一个按曝光累加的商品，和一个按调用累加的商品，不在同一个账本上。

## 二、两个收入公式，并排摆出来

百度的搜索广告，收入＝展示 × 点击率 × 点击单价。三个因子指向同一件事：得有人坐在屏幕前，得有一个货架让他看见，得有一个位置可以卖。位置稀缺，首屏那几个坑位才值得竞价。

这套接口，收入＝成功请求次数 × 千次单价。**公式里没有人。**

客户端可以是 Agent、是 RAG 管道、是 harness。它不「搜索一下」，它直接发请求，拿回一个 `results` 数组，读标题、链接、摘要，然后继续干活。中间不产生一次「看见」，也不产生一次「点击」。

**货架没了，位置就没有落点。**

所以被改写的不只是某家公司的收入结构，是「排名」这个商品的物理基础。检索以 API 形态交付时，交付物是一个结构化数组，不是一个页面。谁在数组里、靠前还是靠后，由检索质量决定——因为这套计价里没有竞价这个环节。

需要重新找饭碗的，是靠「排名」这个商品吃饭的那一层：竞价代运营、按位置报价的排名服务、按曝光承诺的发稿渠道。它们卖的东西，在数组里没有对应的字段。

## 三、三个容易被跳过的细节

**细节一，限速的刻度。**

> For each account, Search and Fetch are limited independently, and traffic to one does not consume the other's quota. Search 100 ／ Fetch 25

—— 同上（Rate Limits 条款）

Search 100 QPS、Fetch 25 QPS，账号级，两者独立配额；Fetch 另有单域名限速，防止对单个站点集中抓取。

100 QPS 是什么量级？按满负荷折算，一天上限 864 万次检索。这个数不是给人用的——一个人一天搜几十次，一个 Agent 一天可以请求几十万次。**限速的刻度本身，就在说明它服务谁。**

**细节二，本地可以做成一个参数。**

`localization` 字段可以传一个 IP 地址，用于本地化检索结果。

本地生活、本地服务一直是搜索广告里占比很重的一块，因为「离我近」天然带交易意图，也天然适合按位置卖。现在它有了一条 API 层的路径：传一个位置，拿回那个位置的检索结果。这未必是替代，但这是把「本地」从一个广告产品，变成一个可以调用的字段。

**细节三，免费的截止日期写着具体时点。**

在 DeepSeek Harness、Claude Code、Codex 里的服务端工具调用，现在免费；**2026 年 11 月 1 日 00:00（北京时间）起按次计费。**

写清楚日期是有意义的。先免费养使用习惯，再按次收钱，这是排期，不是顺手送的福利。免费与计费之间的这次切换，才是这套接口真正开始产生收入的时点。

## 四、还有两个参数，改的是内容怎么写

这一段给真在做内容的人。

**第一个参数，`ori_question`。** 文档说它是可选的，用来传「触发这次检索的用户原始问题」，长度 1 到 128 字符，目的是提升对查询意图的理解。

这个字段的含义比它看起来重。它说明**检索层拿到的不是几个关键词，是一句完整的问题。**

而 SEO 时代的基本功是围绕关键词做布局：把词铺进标题、铺进锚文本、控制出现密度、覆盖近义词。这套动作成立的前提，是检索系统只看得见词。当它同时知道「用户问这句话想干什么」，选源的标准就从「这个词出现了几次」，挪到「这一段能不能回答这件事」。

**第二个参数，`need_content`，加上 Fetch 的返回格式。**

文档写得很直接：Fetch 抓取单个网页，**把内容作为 Markdown 返回**。

换句话说，你的页面在被 Agent 读之前，先被转成了一份纯结构文档。Markdown 里只有标题、列表、表格、引用和段落。

这件事有一个不太被注意的后果：**用图片表达的信息、用脚本渲染出来的信息、折叠在标签页里的信息，在转换那一步就没了。** 一张写着规格和价格的 JPG，转完之后只是一个图片引用，里面的数字一个字都读不到。

这不是偏好问题，是格式转换的物理结果。你把关键事实画在图里，对人友好，对这条链路等于没写。

## 五、AI 引用了谁，第一次可以测

以前测「AI 提没提我」，做法是开几个 App，手动打字问，把回答截图，过两周再问一遍。

这套动作的问题不在麻烦，在**不可复现**：同一个问题今天和明天不一样；开没开联网不一样；甚至同一台机器问两次都不一样。拿到的是抽样，不是基线。

现在多了一条路：固定 `query`、固定 `count`、固定 `need_content`，直接调 Search，拿回结构化的结果列表——每一条都有标题、链接和摘要。

变化在于：**「AI 引用了谁」从一次观察，变成一个可以批量跑、可以复现、可以留证的数据集。**

成本也算得出来：5 元／千次，跑 100 个问句的基线是 0.5 元。这个价位意味着，基线测试不再是咨询公司才做的收费项目，是随手能做的事。

这就是分水岭：**你在问「AI 提没提我」，还是在问「检索层返回了哪些源」。** 前一个只能看见结果，后一个能看见原因。

## 六、手上还有预算，今年能动的四件事

如果这些变化是真的，那手上那笔预算该往哪儿放。四条，都能当场开始。

**第一件，把图片里的关键事实搬回文字。**

这条几乎不用花钱，也很少有人做。产品参数做成九宫格、资质证书拍成图、价格表放在设计图里——这些对人友好，对 Agent 等于空白。把数字用文字写一遍：规格、型号、产地、服务范围、价格区间、联系方式。

不需要重做设计。图片留着，旁边补一段能读的文字就行。

**第二件，让页面变成「能被抽干净」的结构。**

Markdown 只有标题、列表、表格、段落这几种骨架。你的页面被转过去之后，能保住的也是这几种。

具体动作是三件：正文里一个 H2 讲一件事，别把五件事塞进一节；关键数据用文字表格，别用图片表格；一段只说一个意思，超过三句就拆。这些是老式排版纪律，在这条链路里变成了技术条件。

**第三件，换监控口径。**

从「我的关键词排第几」，换成「我进没进 `results`」。前者衡量位置，后者衡量被采信。

每个月固定二十到三十个问句，固定平台、固定日期、固定是否开启联网，记四列：问句、有没有出现、引用了哪个页面、引的是谁家的页面。两周跑一次，跑三个月。这张表的价值会超过任何一张排名截图，因为它记录的是「被采信的位置」，而不是「被排到的位置」。

**第四件，别为「保证进前几」付钱。**

推荐性团体标准 T/CAPT 026—2026 第 8.3 条写得很直接：

> 服务提供方不应承诺或暗示「保证第一」「稳定前三」「永久收录」「必然被大模型引用」「官方推荐合作」「排他性平台合作」等对结果打包票或误导性的效果。

—— T/CAPT 026—2026《生成式引擎优化（GEO）可信信息传播与信息生态治理规范》第 8.3 条（中国新闻技术工作者联合会 2026-08-11 发布；推荐性团体标准，非法律，无监管处罚权）

这不是法律条文，没有处罚权。但它给了一个很省时间的判断：开口就报「能上几个平台、能保证第几」的，这场对话可以直接结束。原因不是对方违规，而是判据换了——当检索层按质量给结果排序，位置就不是可以预先卖出去的东西。

## 七、那 GEO 还有没有用

有，但理由变了。

当客户端是 Agent，它不打开你的网页，它读返回的摘要和正文。所以决定你进不进 `results` 的，不是页面好不好看、停留时长多少，是**你的内容能不能被抓到、被抽干净、被结构化成一个可信条目**。

这恰好是 GEO 里不太像营销的那部分工作：把事实写清楚、把来源标明白、把结构做规整、让同一件事在多个独立页面能对得上。这些动作在新计价体系里的权重没有降低，反而上升了——因为现在有一个环节会按检索质量给结果排序，而这个环节不看谁出价。

反过来，「铺量」这条路的收益在下降。原因不是道德，是算法：当检索层开始按可信度筛信源，铺得越多，被判定成噪声的概率越高。花钱买来的位置，在数组里找不到对应的位置。

所以回到标题那句话：

**一边卖的是「你被看见的机会」，一边卖的是「你被调用的次数」。前一个需要有人在看，后一个不需要。**

这不是一场抢用户的战争。是同一件事换了计价单位。而计价单位一换，靠这个单位吃饭的那一整层，就得重新找饭碗。
